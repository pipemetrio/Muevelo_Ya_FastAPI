### 2. Definición de Códigos de Respuesta HTTP

- **`200 OK`:** La solicitud, consulta, actualización o eliminación fue exitosa.
- **`201 Created`:** El recurso fue creado correctamente en la base de datos.
- **`400 Bad Request`:** Error en la validación de entrada (falta un campo obligatorio o el formato es inválido).
- **`401 Unauthorized`:** No se proporcionó el token JWT o este ha expirado o es inválido.
- **`403 Forbidden`:** El usuario está autenticado pero su rol no posee los permisos suficientes.
- **`404 Not Found`:** El identificador (`id`) solicitado no existe en la base de datos.

### 3. Reglas de Integridad

1. **Restricción de Eliminación de Usuarios:** No se puede eliminar un usuario que tenga direcciones activas o servicios asociados en el historial.
2. **Direcciones Únicas de Servicio:** La dirección de origen (`direccion_origen_id`) y la dirección de destino (`direccion_destino_id`) no pueden ser exactamente la misma para un servicio.
3. **Control de Asignación de Logística:** Un vehículo o transportista marcado como inactivo (`activo = 0` o `disponible = 0`) no puede ser asignado a un nuevo servicio.
4. **Carga Máxima de Vehículo:** El peso total combinado de los objetos en `ObjetoTransporte` vinculados a un servicio no debe superar la `capacidad_kg` del vehículo asignado.
5. **No Cancelación de Servicios Completados:** Un servicio cuyo estado esté en `completado` no puede ser eliminado ni cambiar su estado a `cancelado`.
