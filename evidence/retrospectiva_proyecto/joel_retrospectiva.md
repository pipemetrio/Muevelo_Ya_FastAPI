# Retrospectiva MueveloYa FastAPI Joel Mendoza

Al comenzar a realizar el proyecto de esta forma, mi conocimiento sobre el desarrollo de una API era bastante limitado. Tenía una idea general de cómo funcionaba un backend y podía escribir código en Python debido a algunos conocimientos previos de mi carrera como técnico, a pesar de ello no tenía una visión completa de cómo se estructura y se desarrolla una aplicación web utilizando un framework como FastAPI. Durante las  guías fui entendiendo como desarrollar una API, como crear funciones que reciban y devuelvan información, como organizar el proyecto, manejar una base de datos, validar información, controlar errores, trabajar con autenticación y pensar en la seguridad y el mantenimiento del código.

Antes de iniciar en materia solia conocer Python, pero realmente lo usaba para cosas muy basicas como ejercicios con validaciones usando variables, funciones, clases, ciclos, etc. No habia si quiera contemplado la idea de llevarlo a algo mas grande como lo seria un proyecto, realmente veia a python como un lenguaje solo para eso, solo ejercicios. Me lleve una sorpresa al observar la amplia cobertura del lenguaje gracias al uso de librerias y frameworks. 

Solia ver el código como partes independientes, sin comprender cómo esas partes se relacionan dentro de una aplicación. Aprendí a utilizar FastAPI para construir endpoints y a entender la comunicación entre un cliente y un servidor mediante solicitudes HTTP. 

También aprendí la importancia de métodos como GET, POST, PUT y DELETE, y cómo cada uno representa diferentes operaciones sobre los recursos de una API. Trabajar con modelos, consultas y operaciones CRUD me permitió entender mejor cómo una aplicación almacena y recupera información (Persistencia). También aprendí que una API necesita validar los datos que recibe y no asumir que todo lo enviado por el usuario es correcto. En este sentido, el uso de modelos y validaciones fue importante para comprender cómo FastAPI ayuda a construir aplicaciones más organizadas y confiables.

Uno de los conceptos que más me costó entender fue cómo se relacionan todas las partes de una aplicación backend. Al principio podía comprender un endpoint de manera individual, pero cuando el proyecto empezó a tener diferentes routers, modelos, esquemas, base de datos y autenticación, fue más difícil entender el flujo completo. También tuve que familiarizarme con conceptos que no había utilizado anteriormente o que no comprendía completamente, como el middleware CORS, las variables de entorno y la autenticación mediante tokens, conceptos que, a pesar de que considero que aprendo rapido, me tomo algo de tiempo comprender de forma si quiera basica.

Para resolver estas dificultades mi solución fue practicar y revisar el funcionamiento de cada parte por separado inicialmente. En lugar de intentar comprender todo el proyecto de una sola vez, fui analizando qué hacía cada archivo y cómo se conectaba con los demás. Probar los endpoints mediante Swagger fue de gran ayuda para ello, tambien visualizando como funcionaban los errores que este podria llegarme a mostrar cuando hacia algo mal, podía comprobar directamente qué información recibía la API y qué respuesta estaba generando. Además, buscar explicaciones sobre los conceptos que no entendía me permitió pasar de simplemente copiar una solución a comprender poco a poco por qué funcionaba.

El despligue después de tanto tiempo fue bastante sencillo, ya que ahora comprendo los conceptos, realizar este despligue no tomo mas de 15 minutos, esto tambien gracias a la facilidad e intuitividad que tiene Render y me ayudo a tener una visión más cercana a lo que ocurre en un proyecto real, donde el código debe ejecutarse en un entorno diferente al de desarrollo local, cumplir con ciertos requisitos y que debe tener otras cosas como variables de entorno, comandos de ejecución, dependencias y una buena configuración del servidor.

Si tuviera que comenzar nuevamente a hacer proyecto, haría algunas cosas de manera bastante diferente. como planificar mejor la estructura del proyecto antes de comenzar a programar, ya que un mismo archivo cambio varias veces solo por la falta de planificación (aparte de algún error, bug, etc.). También intentaría avanzar de manera más ordenada, probando cada funcionalidad antes de agregar la siguiente. Honestamente muchas veces simplemente hacia las cosas de forma que funcionen o simplemente hagan algo incluso si no era del todo correcto, lo que despues resulto en una mayor dificultar para corregir los problemas de organización o entender ese código que fue construido rápidamente.

Dedicaría más tiempo desde el principio a comprender la separación de responsabilidades en nuestro equipo de trabajo. Pude concluir gracias a este trabajo que si el proyecto crece, mantener todo en los mismos archivos puede hacer que sea más difícil encontrar errores, modificar funcionalidades o trabajar en equipo (En especial ya que aunque todos estemos usando una misma estructura la logica es bastante por no decir completamente diferente). Por eso, una de las principales cosas que haría diferente sería pensar desde el comienzo en la mantenibilidad del código y no solamente en cumplir con cada funcionalidad.

A pesar de mi aprendizaje, también soy plenamente consciente de que todavía tengo mucho por aprender. El siguiente paso concreto de mi formación como desarrollador sería profundizar en como funcionan realmente la seguridad en FastAPI y comprender realmente las validaciones de Pydantic. Considero que este sería un buen siguiente paso porque ya tengo una base sobre cómo funcionan los endpoints, pero necesito aprender a protegerme mejor de las vulnerabilidades que puedan surgir con cada actualización e incluso el paso del tiempo.

Me gustaria aprender Docker posteriormente, porque permitiría comprender mejor cómo empaquetar y ejecutar una aplicación de manera consistente en diferentes ambientes. Este interes proviene de que por lo muy poco que se Docker permite implementar aplicaciones rápidamente ya que no es necesario iniciar un sistema completo. Pero todavía tengo dificultades y conceptos que necesito reforzar que considero debo priorizar de momento, pero ahora tengo una base más sólida y, sobre todo, una idea más clara de qué necesito aprender después. 

Este proyecto fue un punto de partida y el siguiente paso será profundizar en la arquitectura del backend y en buenas prácticas que me permitan desarrollar proyectos cada vez más completos.
