# Retrospectiva MueveloYa FastAPI Sebastian Ramirez Castrillon

Durante el desarrollo de las siete guías fui reforzando diferentes conceptos relacionados con el desarrollo de APIs y con el proyecto MuéveloYa. Antes de comenzar ya tenía algunos conocimientos sobre APIs y APIs REST, ya que anteriormente había trabajado estos temas utilizando Node.js. Por eso, no empecé completamente desde cero, pero sí tenía algunas cosas que todavía no comprendía del todo y que manejaba más por práctica que por entender realmente cómo funcionaban. Estas guías me ayudaron a reforzar bastante esos conocimientos y a ver una API desde otra tecnología, en este caso utilizando Python y FastAPI.

Durante las guías aprendí y reforcé conceptos como la creación de endpoints, el manejo de solicitudes y respuestas, los códigos de estado HTTP y el trabajo con bases de datos. También entendí mejor cómo se organizan las diferentes partes de un proyecto, por ejemplo, los routers, los esquemas, la conexión con la base de datos y la parte de seguridad. Aunque algunos conceptos ya los había visto con Node.js, trabajar nuevamente con ellos en FastAPI me permitió compararlos y entender que, aunque cambia la tecnología, la idea principal de una API REST se mantiene.

Uno de los temas que más me costó fue la parte de seguridad y autenticación. Al principio no entendía completamente cómo funcionaban los JWT, el Bearer token y los permisos según el rol del usuario. También me costó entender `Depends`, porque FastAPI utiliza las dependencias de una manera que al principio no me resultaba tan clara. Con la práctica fui entendiendo que primero el usuario inicia sesión, se verifica su contraseña, se genera un token y después ese token se utiliza para acceder a los endpoints protegidos. También reforcé la diferencia entre los códigos 401 y 403: el 401 está relacionado con la autenticación y el 403 con los permisos.

Otro concepto que reforcé bastante fueron las consultas SQL preparadas. Ya había trabajado anteriormente con bases de datos, pero durante estas guías entendí mejor por qué se utilizan parámetros como `?` en consultas y cómo esto ayuda a evitar problemas de inyección SQL. También aprendí a reconocer mejor el uso de Pydantic para validar los datos que recibe la API.

Si tuviera que empezar el proyecto nuevamente, intentaría organizar mejor el trabajo desde el principio. Primero trataría de entender la estructura del proyecto y la función de cada archivo antes de comenzar a modificar código. También probaría cada parte poco a poco y no dejaría varias cosas para el final. Creo que esto me ayudaría a encontrar los errores más rápido y a entender mejor cómo se conectan entre sí la base de datos, los routers, los esquemas y la seguridad.

Las siete guías también me ayudaron a entender que desarrollar una API no es solamente crear endpoints. También es necesario probarlos, revisar los errores y comprobar qué sucede cuando los datos son incorrectos o cuando un usuario no tiene permisos. Con Swagger mediante `/docs` pude probar diferentes endpoints y observar respuestas como 200, 201, 401, 403, 404 y 422. Esto reforzó conocimientos que ya tenía sobre APIs REST, pero de una manera más práctica y completa.

Actualmente considero que todavía estoy en una etapa de aprendizaje y que no domino completamente estos temas. Sin embargo, sí siento que tengo una mejor base que antes. Ahora puedo entender con mayor facilidad la estructura de una API y reconocer conceptos como FastAPI, Pydantic, SQLite, JWT, bcrypt, consultas SQL y dependencias. También considero que haber trabajado anteriormente con Node.js me ayudó a entender más rápido algunas partes, porque ya conocía la idea general de cómo funciona una API REST.

Como siguiente paso concreto de mi formación, considero que debería profundizar en la inyección de dependencias con `Depends`, porque ya la utilicé en el proyecto pero todavía quiero entenderla mejor y no solamente saber cómo utilizarla. Después me gustaría aprender a separar mejor la capa de acceso a datos y posteriormente conocer un ORM como SQLAlchemy. Más adelante podría continuar con pruebas automatizadas usando pytest y con Docker. Por ahora considero que lo mejor es fortalecer estos conceptos antes de intentar aprender demasiadas herramientas al mismo tiempo.

En conclusión, las siete guías me permitieron reforzar los conocimientos que ya tenía sobre APIs REST y complementarlos con nuevos conceptos utilizando FastAPI. Pasé de conocer algunas cosas principalmente por haberlas practicado con Node.js a tener una comprensión un poco más clara de cómo se relacionan las diferentes partes de una API. Todavía tengo mucho por aprender, pero considero que estas guías me dejaron una mejor base para continuar mi formación como desarrollador.
